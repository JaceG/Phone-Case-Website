# Imagery pipeline

Goal: adding a design is **one artwork upload**; every product image renders
itself. Runs are manual for now; the folder layout is shaped so a Payload
hook can later hand work to a headless Blender worker without reorganising.

```
pipeline/
  blender/
    build_shell.py    # parametric shell builder: params JSON -> master.blend
    shell_geometry.py # profiled silicone shell, openings, lens lips and UV repair
    validate_shell.py # geometry/openings/shared-UV checks on a built blend
    params/           # one JSON of case dimensions per blank (mm)
    uv-checker.png    # default texture baked into master.blend (generated)
    master.blend      # shell, UV, materials, cameras, lights (generated by build_shell.py)
    render.py         # batch renderer, run headless
  designs/            # INPUT  — artwork masters, <slug>.png, one per design (gitignored)
  out/                # OUTPUT — <slug>_<camera>.png (gitignored)
  scripts/
    uv-checker.ts     # numbered UV checker generator
    import-renders.ts # pipeline/out -> Payload media + product.renders
```

Blender is installed at `/Applications/Blender.app` but not on `PATH`; the
commands below spell out the binary. Everything runs from the repo root.

## 1. Build the shell (`master.blend`)

```bash
# default texture the blend opens with (10 px/mm of the 107 × 191 mm template)
pnpm tsx pipeline/scripts/uv-checker.ts pipeline/blender/uv-checker.png 1070 1910

/Applications/Blender.app/Contents/MacOS/Blender -b -P pipeline/blender/build_shell.py -- \
  --out pipeline/blender/master.blend \
  --params pipeline/blender/params/iphone-17-pro-max.json
```

Rebuild whenever a params file changes — the blend is
disposable output, the JSON and geometry profiles are the source. See `notes` in the params file for
which numbers are measured and which are placeholders.

The September 12 shell follows the supplied silicone-blank photographs:
rolled back edges, rounded open rim and interior fillet; a broad 72 × 43 mm
camera surround with a recessed deck; three thin lens lips and separate
flash/microphone/sensor openings; shallow MagSafe grooves; four side controls,
a bottom charging opening and six speaker perforations. Profiles explicitly
form the shell thickness. Lens lips are separate closed meshes, avoiding the
old union operation that streaked the camera-deck UVs.

`case_print` uses `case_artwork` for base colour, roughness 0.57 and subtle
procedural grain. `case_inner` uses the params' `silicone_color` (lavender by
default), roughness 0.65. Four broad studio lights and AgX soften highlights.
The renderer exports transparent PNGs for the light editorial storefront.
All nine mesh parts share `turntable_pivot`; cameras stay stationary.

Camera sizes: `hero` and `three_quarter` 1200 × 1500; orthographic `flat`
1024 × 2048; `turntable` 768 × 768; hero tumble 640 × 640. Review-only cameras
`detail` (1400 × 1100) and `interior` (1200 × 1500) use Cycles too.

## 2. Render designs

Artwork goes in `pipeline/designs/<slug>.png` where `<slug>` is the product's
slug; the file name is what links a render to a product. Synthetic checkers for
the three seeded designs:

```bash
pnpm tsx pipeline/scripts/uv-checker.ts pipeline/designs/meridian.png     1070 1910 220 MERIDIAN
pnpm tsx pipeline/scripts/uv-checker.ts pipeline/designs/static-bloom.png 1070 1910 290 "STATIC BLOOM"
pnpm tsx pipeline/scripts/uv-checker.ts pipeline/designs/low-tide.png     1070 1910 165 "LOW TIDE"
```

```bash
/Applications/Blender.app/Contents/MacOS/Blender -b pipeline/blender/master.blend -P pipeline/blender/render.py -- \
  --designs pipeline/designs --out pipeline/out/refined --cameras hero three_quarter flat \
  --turntable 24 --tumble 288 --tumble-boost 37.6 --tumble-halfwidth 0.14 --samples 96
```

Flags: `--only <slug>…` renders a subset; `--turntable N` sets the frame count
(0 disables); `--samples` are the Cycles samples for the hero shots; `--cpu`
forces Cycles off the GPU. Cycles uses Metal when available; first-use kernel
compilation can take longer. The approved hero motion is a fixed tilted axis,
288 time-distributed frames, roughly 2.5 seconds near the front and 1.05 seconds
for edges/back. Preserve both speed flags and the generated `<slug>_tumble.json`
phase sidecar when regenerating. `SpinningRender.tsx` consumes those phases.

For a plain-colour material proof independent of artwork:

```bash
/Applications/Blender.app/Contents/MacOS/Blender -b pipeline/blender/master.blend -P pipeline/blender/render.py -- \
  --designs pipeline/designs --out pipeline/out/review/lavender --only meridian \
  --surface-color b4a6d1 --cameras hero three_quarter detail interior --samples 96
```

This overrides material colours only for that render session; it does not
change the saved blend or the artwork masters.

## 3. Import into Payload

```bash
pnpm renders:import                      # everything in pipeline/out
pnpm renders:import meridian            # one design (payload run strips flags)
RENDERS_OUT=pipeline/out/refined RENDERS_KEEP_PREVIOUS=1 pnpm renders:import
```

Uploads each `<slug>_<camera>.png` to `media` (alt `"<Title> — <camera>
render"`), sets `renders.hero` / `threeQuarter` / `flat`, `renders.turntable`
(ordered frames), `renders.tumble` / `tumblePhases`, and `renderStatus = 'ready'`
on the product with that slug. Loops are converted to WebP during import.
By default it deletes media from earlier runs (matched by that alt text). Uses the local
API straight against Postgres; the dev server does not need to be up.

For review iterations, `RENDERS_KEEP_PREVIOUS=1` saves the old product render
relationships in `<out>/previous-renders/<timestamp>/<slug>.json` and retains
their media. The September 12 pre-edit model, source and sample renders are
also in `pipeline/out/review/baseline/`. These ignored local copies preserve
the prior uncommitted shell; do not use a git reset to recover it. A later
import without `RENDERS_KEEP_PREVIOUS=1` can delete that retained media.

## Contract between `master.blend` and `render.py`

- An image datablock named **`case_artwork`** drives the base colour of the
  printable face. Its filepath is the only per-design change.
- Camera objects named **`hero`**, **`three_quarter`**, **`flat`**, and
  **`turntable`**; an empty named **`turntable_pivot`** that the script
  rotates around Z (the shell is parented to it, the camera is not).
- Optional per-camera custom props `res_x` / `res_y` set the output size.
- Hero and three-quarter render with Cycles; flat and turntable with EEVEE.
  `render.py` reads the EEVEE engine id from the enum (`BLENDER_EEVEE` on
  5.x, `BLENDER_EEVEE_NEXT` on 4.2–4.x).
- Output naming is `<design-slug>_<camera>.png` and, for turntables,
  `<design-slug>_turntable_<frame:03>.png`. `import-renders.ts` (and the
  future Payload worker) look for exactly these.

## UV map ↔ print template: one coordinate space

The printable surface uses **one shared rectangle** for artwork placement.
This is the draft template coordinate system; a measured supplier dieline and
an applied-film test are still needed before treating it as a physical proof.
The inside, lens lips, buttons and cut walls use plain silicone material.

Template size in mm: `(width + 2·depth) × (height + 2·depth)`; for the
iPhone 17 Pro Max blank, `(81 + 26) × (165 + 26) = 107 × 191 mm`. The artwork
master must have exactly that pixel aspect — at 10 px/mm, **1070 × 1910 px**
(`pipeline/scripts/uv-checker.ts` defaults to this). The blend records the
figures as scene custom props `print_template_mm` / `print_template_px`.

Layout, as seen from outside the back (image left = viewer's left, image top =
phone top; UV `u` runs left→right, `v` bottom→top):

```
      ┌──────────── 107 mm ────────────┐
      │ ╭╌╌╌╌╌╌╌╌╌ top wall ╌╌╌╌╌╌╌╌╌╮ │  13 mm
      │ ┆ ┌────────────────────────┐ ┆ │
      │ l ┆                        ┆ r │
      │ e ┆   back face 81 × 165   ┆ i │  191 mm
      │ f ┆   (camera island and   ┆ g │
      │ t ┆    cutout inside it)   ┆ h │
      │   ┆                        ┆ t │
      │ ┆ └────────────────────────┘ ┆ │
      │ ╰╌╌╌╌╌╌╌╌ bottom wall ╌╌╌╌╌╌╌╌╯ │  13 mm
      └────────────────────────────────┘
       13 mm                       13 mm
```

- **Back face** occupies the centre rectangle: template `(depth + x, depth + y)`
  for a point `(x, y)` measured from the back's bottom-left corner.
- **Side walls** fold outward into the reserved edge strips. The profiled
  shoulder uses a depth-based approximation, `point + outward_normal · t`,
  with `t = max(0, -z - back_roll_mm * 0.35)` in build coordinates. This keeps
  existing artwork framing while softening the physical edge. It is not an
  arclength flattening or compensation for film stretch.
- **Rounded corners** fan radially: the corner arc of radius `r` extends to
  radius `r + depth`, so the template's four corner squares are only partly
  used (the unused bits are what the die cuts away). The film stretches here
  in reality too.
- **Camera island**: all UVs are reprojected after cuts and bevels, using the
  same XY mapping as the back. Artwork crosses the deck without the previous
  triangulation streaks. Its curved surround still uses planar projection;
  real film behaviour over that step is not simulated.

Check numbered cells on the flat back and camera deck for alignment, and the
outer rows/columns on the walls for continuity. Some distortion on compound
curves is expected from this draft mapping. The checker is diagnostic artwork,
not a design intended for sale.

Every number that shapes this space is in `params/*.json`. The envelope is from
the supplier listing; wall thickness, corner radius, island and cutout are
placeholders until calipers replace them.

## Rules (from the project brief)

- Validate with a numbered UV checker, not real artwork
  (`pnpm tsx pipeline/scripts/uv-checker.ts`).
- Product pixels are truthful: case, print, colour, cutouts. Environment,
  light, atmosphere and motion may be synthetic.
- Nothing borrowed in `designs/`; only originals, licensed art or generated
  test textures.

## Shell parameters: holes, rims, MagSafe ring

Every blank is model-specific because of the **holes**, not the envelope.
`params/<model>.json` therefore carries:

- `camera_island` — the raised plateau (top-left offset, size, height, corner radius).
- `holes[]` — one entry per opening, centre `x_mm`/`y_mm` measured from the
  island's top-left corner as seen from outside, plus `d_mm`. `kind` is
  `lens` | `flash` | `mic` | `sensor`; only `lens` holes get a raised rim.
- `lens_rim` — lip width (outward from the hole edge) and height above the island.
- `magsafe_ring` — moulded ring and alignment line, cut as shallow grooves
  in the back; the artwork continues across them (groove faces keep the
  print material and projected UVs).

All hole diameters and positions are placeholders traced from the reference
photos of the silicone blank; replace with caliper numbers per model, then
rebuild (`build_shell.py`) and rerender. The corner segmentation, opening
segmentation, edge bevel, back roll, silicone colour and side-control placement
are also configurable. Bottom opening dimensions and the profile shapes live
in `shell_geometry.py`.

## Validate a generated model

```bash
/Applications/Blender.app/Contents/MacOS/Blender -b pipeline/blender/master.blend \
  --python-exit-code 1 -P pipeline/blender/validate_shell.py
```

Checks closed parts with outward normals, unobstructed camera openings, the
81 × 13 × 165 mm shell envelope in scene axes, and numeric artwork-coordinate
agreement on the back and camera deck. Also inspect plain-colour close-ups,
interior renders, numbered-checker stills, and the actual moving storefront.

Reference: [supplier blank listing](https://www.alibaba.com/product-detail/Dust-Repellent-Smooth-Color-Liquid-Silicone_1601927395824.html)
and Jace's local photos. Geometry is an interpretation of those photos, not
supplier CAD. Only the supplied outer envelope is grounded in listing dimensions.

## Interactive Case Studio (local draft)

Open `http://localhost:3000/case-studio` while the development server is running.
Upload JPG/PNG/WebP artwork, drag it on the flat template, or use the width,
position and rotation sliders. Arrow keys move one template pixel; Shift moves
ten. `Portrait fit` places the full image in the lower 70% of the case back;
`Fill case` covers the selected print area's bounding rectangle. Background and plain silicone colors are
independent. Artwork is drawn at its original aspect ratio over a solid background,
with no gradient or fade over the source image. Older saved projects retain their
placement and colors but ignore the removed top-edge fade.

**Print area** switches between Wraparound (back, rolled shoulders, sidewalls and
camera deck) and Back only (back face and camera surround, with solid outer sides). Switching
keeps the image's size, position and rotation unchanged; clipped artwork is
restored when switching back. The mode is saved with the project; older projects
default to Wraparound. The Back only mask uses the model's 2 mm shoulder inset
and individual lens/flash/sensor openings, not a measured production insert template.

The flat panel's **Artwork zoom** buttons and slider directly resize the image
on the device, with its aspect ratio locked and center retained. 100% means the
image is as wide as the modeled case back. Scroll or pinch over the flat layout
to resize the artwork; `+`/`-` do the same when the layout is focused. Drag or
arrow keys change placement. The template itself stays fitted in the panel.
The former view-only zoom/pan controls have been removed to avoid ambiguity.

The live Three.js preview uses the actual Blender mesh and UV coordinates.
Orbit with a drag, zoom with the wheel/pinch, or select Artwork / Angle / Inside.
The shared canvas stays 1070 × 1910, matching Blender's UV space. Wraparound
exports that full rectangle. Back only exports the 770 × 1610 flat-face bounds,
with transparent rounded corners and individual lens/flash/sensor cutouts. Both exclude the guide
overlay. Artwork zoom is reflected in the exported print. The live texture composites unprinted areas over the
chosen Case & rim color, so the outer sidewalls remain solid in
Back only. Interior and cut walls retain their plain material. Lighting is a
quick neutral preview, not a color proof. Filenames include the print mode.

Export layout, Save 3D view, and Save project write local files into ignored
`placeholder/case-studio/exports/` and also attempt a browser download. The
Saved files section always retains accessible local copies, including in the
embedded browser. Reopen project restores the source and all placement/finish
settings; Open project accepts a downloaded `.case-studio.json` file. Uploads
stay in browser memory until explicitly saved. No Payload catalog records are
created. The page, example image, and all saved-file endpoints return 404 outside
development. The optional Gohan example comes from the existing ignored source.

The committed web asset contains original shell geometry only, no artwork.
After rebuilding `master.blend`, regenerate it with:

```bash
/Applications/Blender.app/Contents/MacOS/Blender -b pipeline/blender/master.blend \
  --python-exit-code 1 -P pipeline/blender/export_web.py
```

This exports `public/models/iphone-17-pro-max.glb`. The editor derives its flat
guides and template dimensions from the same model params JSON. It currently
supports this single shell. Curved-surface flattening remains approximate until
the physical blank and actual print process are tested.
